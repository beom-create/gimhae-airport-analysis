## 탑승객 수는 "실측"이라고 단정하지 않는다

- 엔드포인트 이름이 `daily-expect-passenger`(**예상** 승객)이고, 내일(D+1) 값도 조회된다. 명세에는 실적/예상 구분이 없다.
- 그래서 보고서·웹에서는 **"탑승객 수(한국공항공사 시간대별 탑승승객 수 API 제공값, 실적 여부 확인 필요)"** 로 표기하고 "실측", "실제 탑승객"이라고 쓰지 않는다.
- 판단 근거 수집: `collect_passengers.py`가 매 실행마다 D-7~D+1을 다시 받아, 저장된 값과 다르면 `data/passengers_changes.csv`에 기록 (`days_after_SDT` = 운항일로부터 며칠 뒤 바뀌었나). `check.py`가 요약.
  - 날짜가 지난 뒤(`days_after_SDT ≥ 1`)에도 값이 바뀌면 → 실적으로 사후 갱신될 가능성
  - 계속 안 바뀌면 → 사전 예상값이 고정된 것일 수 있음 (이 경우도 실측이라 단정하지 않음)
- 수집 2주쯤 뒤 변경 기록을 보고 표기 문구를 다시 정한다. 공사 담당 부서(02-2660-4803) 문의도 선택지.

## ASOS 강수량(`rn`) 처리 규칙 (Phase 3에서 적용)

1년치 데이터(2025-11 ~ 2026-11)를 확인한 결과:

| 원본값 | 253 김해시 | 159 부산 | 처리 |
|---|---|---|---|
| 빈값 `""`, `rnQcflg` 빈값 | 다수 | 다수 | **강수 없음 → 0** (가이드상 플래그 빈값 = 정상) |
| `"0.0"` | 199시간 | 297시간 | **0** (관측됐지만 0.05mm 미만 등 아주 약한 강수일 수 있음 → `rain_trace=1` 파생변수로 따로 표시) |
| 빈값 `""`, `rnQcflg = 9` | 1,123시간 | 1,206시간 | **결측** (가이드 플래그표: null 정상 / 1 오류 / 9 결측). 0으로 채우지 않음 |
| `rnQcflg = 1` | 0 | 0 | 오류 → 결측 처리 |

- **3시간 간격**: 11월~3월은 비 온 값이 00·03·06·…·21시에만 나옴(4~10월은 매시간). 이 기간 `rn`은 **앞 3시간 누적값**으로 보고,
  - `rain_3h` = 그 값, 사이 시간(예: 01·02시)은 같은 3시간 구간의 값을 공유해서 `강수 여부`를 판단
  - 시간당 강수량으로 나누어 쓰지 않음 (분포 가정을 만들지 않기 위해)
  - 3시간 간격 월 구분은 관측 결과 기준. 가이드 문구 확인 필요
- 원본은 `data/weather.csv`에 그대로 두고, 변환은 전처리 스크립트에서만 한다.

## 스케줄 API: 끝난 편 거르기

- `lastdate`(정기운항 종료일) **< 수집일**이면 제외, `fgenType = "D"`(삭제)도 제외 (`collect_schedule.py`의 `is_active`).
- 응답에는 2024~2025년 지난 시즌 스케줄이 섞여 있음 (국내 1,157건 중 984건, 국제 2,847건 중 2,531건 제외 → 유효 487건).
- `schedule.csv`는 실행마다 "그날 유효한 스케줄"로 덮어씀. 분석 기간 중 시즌이 바뀌면(다음 시즌 시작 2027-03 말 예상) 커밋 이력으로 이전 상태 확인 가능.
