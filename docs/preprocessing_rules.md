# 전처리 규칙 (Phase 3) — `src/preprocess.py`

결과: `data/processed/departures.csv` (김해 출발 실제 운항편 1편 = 1행). 기준값은 `src/config.py`.

## 1. 대상 행
| 단계 | 규칙 | 이유 |
|---|---|---|
| 판매 편명 중복 제거 | `masterflightid`가 비었거나 `flightid`와 같은 행만 | 같은 비행기를 여러 항공사가 판매 (docs/decisions.md) |
| 날짜 | `ANALYSIS_START`(11/9) ~ **어제**까지 | 오늘 편은 상태가 아직 확정 안 됨 |
| 출발편 | `io = O` | 타겟이 출발 지연 |
| 결항 | `rmkKor`에 "결항" 포함 → 제외, 건수는 별도 보고 | 지연 여부를 정의할 수 없음 |
| 실제 시각 없음 | 제외 | 타겟 계산 불가 |

## 2. 타겟
- `delay_min` = 실제 출발 − 예정 출발 (분). **실제 시각은 이륙 기준으로 추정** (docs/decisions.md)
- `delayed` = `delay_min` > 국내 30분 / 국제 60분 (국토부 구 기준, 활주로 기준) → 1, 아니면 0
- `delayed_gate15_ref` = 15분 초과 (현행 게이트 기준, **참고용**, 측정 시점이 달라 모델에 안 씀)
- `delay_min`, `delayed_gate15_ref`는 feature에 절대 넣지 않음 (누수)

## 3. Feature (운항 전에 알 수 있는 값만)
| feature | 만드는 법 |
|---|---|
| `sched_hour`, `time_band` | 예정 출발 시각, 6구간(00-05 심야, 06-08 아침, 09-11 오전, 12-14 점심, 15-17 오후, 18-20 저녁, 21-23 밤) |
| `dow`, `dow_name`, `is_weekend`, `is_holiday` | 예정 날짜. 공휴일 목록은 `config.HOLIDAYS` (확인 필요) |
| `line`, `airline`, `dest` | 운항 계획 |
| `n_codeshare` | 같은 비행기를 판매하는 다른 편명 수 |
| `sched_dep_same_hour`, `sched_arr_same_hour` | 같은 날·같은 시각대(정시 단위) 예정 출발/도착 실제 운항편 수 |
| `exp_pax_line_hour`, `exp_pax_total_hour` | 예상 탑승객 수(출발, 같은 시각대, 국내/국제 별·전체). **공사 사전 예상치, 실측 아님** |
| `ta`, `ws`, `vs`, `hm` | ASOS 김해시(253), **예정 출발 1시간 전** 관측값 (출발 시각 관측값은 출발 후에 확정되므로 안 씀) |
| `rain_3h_mm`, `rain_3h_state`, `rain_3h_missing` | 1시간 전 시점까지 **직전 3시간** 강수 합계 / 비·없음·기록결측 / 결측 지표 |

## 4. 결측·이상값
| 항목 | 규칙 | 근거 |
|---|---|---|
| 강수 빈값 + 품질플래그 정상 | 0 | 가이드 플래그표: null = 정상 |
| 강수 `0.0` | 0 | |
| 강수 플래그 9(결측)·1(오류) | 결측 → 부산(159) 같은 시각 값으로 보완 | 253 결측 시간대 159 강수 비율 2.4%(전체 5.4%) |
| 보완 후에도 결측 | `rain_3h_state = 기록결측` 별도 범주, 모델 수치 입력은 중앙값 대치 + `rain_3h_missing` 지표 | 두 관측소가 **같은 날 함께** 플래그 9인 경우가 대부분이고, 플래그 9가 15시간 이상인 날의 82%가 비 온 날 → 0으로 채우면 비를 숨길 수 있음. 플래그 9의 정확한 의미는 확인 필요 |
| 11~3월 3시간 간격 강수 | "직전 3시간 창 합계"로 계산 → 1시간 간격 달과 같은 규칙 | 관측 결과 11~3월은 00·03·…·21시에만 값 |
| 기온·풍속·시정·습도 결측 | 159 값으로 보완 → 남으면 모델에서 중앙값 대치 | |
| 지연 분 이상값 | 현재 제거하지 않음 (음수 = 조기 출발 포함). 12월 최종 데이터로 분포 확인 후 결정 | 타겟은 기준 초과 여부라 극단값 영향이 작음 |

## 5. 모델 단계 처리 (`src/model.py`)
- 수치: 중앙값 대치 (+ 로지스틱 회귀는 표준화). 범주: 최빈값 대치 + One-hot
- feature 조정은 학습 데이터만으로 결정 → `outputs/model/feature_adjustment_log.txt`
